# 用語説明

このドキュメントに登場する主要な用語をまとめます。初めて触れる技術が多い場合は、先にここを読んでおくとスムーズです。

---

## 開発環境・ツール

### Xcode
Apple が提供する **macOS 専用の統合開発環境（IDE）**。iOS / macOS アプリの開発・ビルド・実機へのインストールに使います。App Store から無料でダウンロードできますが、約 10 GB と大きいです。

このデモでは「ビルド（コードを実行可能なアプリに変換）」と「実機への転送」のために Xcode を使います。直接 Xcode でコードを書く必要はありません。

### Command Line Tools（CLT）
Xcode に付属するコマンドラインツール群。`git` や各種コンパイラが含まれます。`xcode-select --install` でインストールします。多くのツールが内部で依存しているため、Xcode をインストールした後に必ず設定が必要です。

### Node.js
JavaScript をブラウザの外（サーバーやターミナル）で動かすための **実行環境**。React Native / Expo のビルドツールや CLI がすべて Node.js 上で動くため、開発マシンへのインストールが必要です。バージョン 20 以上を推奨しています。

### npm（Node Package Manager）
Node.js に付属する **パッケージ管理ツール**。`npm install` で `package.json` に記載された依存ライブラリをまとめてダウンロードします。`node_modules/` フォルダに保存されます。

### nvm（Node Version Manager）
Node.js の複数バージョンを切り替えて管理するツール。プロジェクトごとに異なる Node.js バージョンを使いたい場合に便利です。このデモでは必須ではありませんが、インストールしておくと便利です。

### CocoaPods
iOS / macOS 向けの **依存ライブラリ管理ツール**（Ruby 製）。`npm install` が JavaScript のライブラリを管理するように、CocoaPods はネイティブ（Swift / Objective-C）のライブラリを管理します。

Expo が内部で利用しており、`npx expo run:ios` 実行時に自動で `pod install` が走ります。初回は数分かかります。

### SDK（Software Development Kit）
あるプラットフォーム向けのアプリを開発するために必要な **ライブラリ・ツール・API・ドキュメントをまとめたもの**。「開発キット」という意味で、これ一式があればそのプラットフォーム向けの開発を始められます。Expo の場合は後述の「Expo SDK」がこれにあたります。

### CLI（Command Line Interface）
ターミナル（コマンドライン）から文字コマンドで操作する方式・ツールのこと。GUI（画面のボタン操作）の対義語です。このデモで使う `npx expo ...` は Expo の CLI で、ビルドや prebuild をコマンドで実行します。

## アプリフレームワーク

### React Native
JavaScript / TypeScript で **iOS・Android 両方のネイティブアプリ**を開発できるフレームワーク（Meta 製）。HTML ではなく、iOS の UIKit・Android の View に変換されるコンポーネントを使って UI を組みます。

### Expo
React Native の開発を楽にするツールセット・プラットフォーム。ビルドツール・CLI・各種ネイティブ機能のラッパーライブラリが揃っています。このデモでは `expo prebuild` と `expo run:ios` を使います。

### Expo Go
Expo が App Store / Google Play で配布している **プレビュー用の"完成品アプリ"**。QR コードをスキャンするだけで、自分で書いた JavaScript を即座に実機で試せます。インストールやビルドが不要で、最初の学習・プロトタイピングに向いています。

ただし **中身（同梱されるネイティブモジュール）は Expo が決め打ちした固定**で、利用者が後からネイティブモジュールを追加することはできません。

- **JS だけのライブラリ** → Expo Go 上でもそのまま動く（JS は実行時に読み込まれるため）
- **独自のネイティブモジュール**（このデモの `react-native-beacon-radar` など）→ **追加できない**。ネイティブコードはアプリにコンパイルして焼き込む必要があり、既成の Expo Go バイナリには入れられない

→ このため独自ネイティブモジュールを使う場合は、後述の **開発ビルド（Dev Client）** を自分でビルドして使います。

### 開発ビルド（Dev Client）
Expo Go の代わりに使う、**自分のアプリ専用のランタイム**。`expo-dev-client` パッケージを追加して `npx expo run:ios` でビルドすると、独自ネイティブモジュールを含んだアプリが実機にインストールされます。

> **Expo Go ⇄ 開発ビルド** が「開発中に実機で何を動かすか」の対照ペアです（後述の EAS とは別の軸）。

### Expo SDK
Expo が **バージョンごとに提供するライブラリ群のセット**。React Native 本体と、よく使うネイティブ機能（カメラ・位置情報・通知など）のラッパーがまとめられています。`Expo SDK 54` のようにバージョンで管理され、対応する React Native のバージョンが決まっています。このデモは SDK 54 を使っています。

### EAS（Expo Application Services）
Expo が提供する **クラウド上のビルド・配布サービス**。`eas build` コマンドで、自分の Mac でビルドする代わりに **クラウドで iOS / Android アプリをビルド**できます（Windows しか無くても iOS ビルドが可能）。TestFlight や App Store への提出も `eas submit` で行えます。

EAS は「**どこでビルドを作るか**（ローカル vs クラウド）」の選択肢であり、Expo Go の代わりに実機で動くものではありません。開発ビルドも本番ビルドも EAS で作れます。

| | ローカルビルド（本デモ） | EAS Build |
|---|---|---|
| ビルド場所 | 自分の Mac（Xcode） | Expo のクラウド |
| コマンド例 | `npx expo run:ios` | `eas build` |
| Mac の要否 | iOS は Mac 必須 | 不要 |

> **このデモで EAS を使わない理由**: EAS でビルドしたアプリを iPhone 実機に入れるには ad hoc 配布となり、[**有料の Apple Developer Program（年 $99）が必須**](https://docs.expo.dev/build/internal-distribution/)です（無料の Apple ID では実機に入れられません）。無料で動作確認できるよう、本デモは **ローカルの Xcode ビルド（無料の Personal Team）** を採用しています。

### TypeScript
JavaScript に **型（型注釈）** を追加した言語。コンパイル時に型の誤りを検出できるため、バグを早期に発見しやすくなります。このデモのソースコードは `.ts` / `.tsx` 拡張子で TypeScript を使っています。

## Bluetooth / iBeacon

### BLE（Bluetooth Low Energy）
Bluetooth の省電力版規格。少ない電力で定期的にデータを発信できるため、iBeacon のようなセンサーデバイスに広く使われています。

### iBeacon
Apple が策定した **BLE ビーコンのプロトコル**。UUID・Major・Minor という 3 つの識別子を持つ信号を定期的に発信します。iOS は CoreLocation フレームワークを使って iBeacon を検出します。

| 識別子 | 説明 |
|---|---|
| UUID | ビーコングループの識別子（36 文字の文字列） |
| Major | グループ内の大分類（0〜65535 の整数） |
| Minor | グループ内の小分類（0〜65535 の整数） |

### RSSI（Received Signal Strength Indicator）
受信した電波の**強度**を示す値。単位は dBm（デシベルミリワット）。値が 0 に近いほど強く、-100 に近いほど弱い信号です。距離の目安として使えますが、障害物や反射の影響を受けます。

| RSSI の目安 | 距離感 |
|---|---|
| -40 〜 -60 dBm | 非常に近い（50cm 以内） |
| -60 〜 -75 dBm | 近い（1〜2m） |
| -75 〜 -90 dBm | やや遠い（3〜5m） |
| -90 dBm 以下 | 遠い・不安定 |

## Apple 関連

### Apple ID
Apple サービス全般のアカウント。Xcode へのサインインにも使います。

### Apple Developer アカウント（無料）
Apple ID で `developer.apple.com` にアクセスして登録すると取得できる **無料の開発者登録**。これだけで自分の iPhone に開発ビルドをインストールできます。

> **自分のスマホだけで確認する場合、有料プランは不要です。**
> 無料の Apple Developer 登録（Apple ID でサインインするだけ）で実機インストールは可能です。

### Apple Developer Program（有料・年間 $99）
App Store への公開や TestFlight を使った配布に必要な **有料プラン**。自分の端末で動作確認するだけなら加入不要です。

### TestFlight
Apple が提供する **iOS アプリのベータ配布サービス**。App Store で一般公開する前に、招待したテスター（最大 1 万人）に手元の iPhone でアプリを試してもらえます。手順の概要は以下の通りです。

1. アプリのビルドを **App Store Connect** にアップロードする
2. テスターをメール等で招待する
3. テスターは **TestFlight アプリ**（App Store で配布）経由でインストールする

- **必須条件**: 有料の **Apple Developer Program**（無料の Personal Team では使えません）。
- **ビルドのアップロード手段は任意**: Xcode の Organizer / Transporter で手動アップロードするか、**EAS**（`eas build` → `eas submit`）でクラウドから自動アップロードします。つまり **TestFlight に EAS は必須ではなく、便利な選択肢の一つ**です。
- このデモは自分の実機で動作確認するだけなので、TestFlight は使いません。

### Signing（署名）
iOS アプリは Apple の証明書で署名しないとインストールできません。Xcode の **Signing & Capabilities** で Apple ID を選択し「Automatically manage signing」をオンにすると、Xcode が証明書を自動生成・管理してくれます。

### Bundle Identifier
アプリを一意に識別する文字列（例: `jp.co.fusic.ibeacondemo`）。ドメインを逆順にした形式が慣例です。Apple Developer アカウントのデバイス登録や署名の際に使われます。

## ビルド関連

### prebuild（`npx expo prebuild`）
`app.json` の設定を元に **iOS ネイティブプロジェクト（`ios/` ディレクトリ）を自動生成**するコマンド。`plugins` に指定したパッケージの設定（パーミッション宣言など）が `Info.plist` や `Podfile` に自動で書き込まれます。

### Info.plist
iOS アプリの **設定ファイル**（XML 形式）。Bluetooth や位置情報を使う場合、ユーザーに表示するメッセージをここに記載する義務があります。Expo prebuild が `app.json` の内容から自動生成します。

### Metro
React Native / Expo の **JavaScript バンドラ兼開発サーバー**。プロジェクト内の多数の `.ts` / `.tsx` ファイルを 1 つの JS にまとめ（バンドル）、実機やシミュレータのアプリへ配信します。

`npx expo run:ios` や `npx expo start` を実行すると Metro サーバーが起動し、アプリ（Expo Go や開発ビルド）はここから JS を読み込みます。コードを保存すると変更が即座に反映される **Fast Refresh** も Metro が担っています。

> ネイティブ部分はビルド時にアプリへ焼き込まれる一方、**JS 部分は Metro から実行時に読み込まれる**ため、JS の変更だけなら再ビルド不要で反映されます。

### `npx`
npm に付属するコマンドで、**パッケージをインストールせずに一時的に実行**できます。`npx expo ...` のように使います。
